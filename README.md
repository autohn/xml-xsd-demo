# XSD → форма → XML

Демо: выбираете XSD-схему из корня проекта — по ней на лету строится вложенная форма (React + shadcn/ui + Tailwind v4 + zod). Значения валидируются по схеме, готовый XML можно скачать.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # 43 теста, включая проверку XML через xmllint (libxml2) по реальным XSD
npm run build      # статическая сборка в dist/ (base './', работает с любого пути)
```

## Как это работает

1. **Схемы** — `*.xsd` из корня подхватываются через `import.meta.glob` (`src/lib/schemas.ts`). Новый файл в корне сразу появляется в списке.
2. **Загрузчик** (`src/xsd/loader.ts`) разбирает XSD в модель (`src/xsd/model.ts`): элементы, простые/сложные типы, `sequence`/`choice`/`all`, `group`, `extension`/`restriction`, атрибуты, `xs:any`, фасеты, импорты (по имени файла).
3. **Форма** — дерево значений (`ElementInst`) повторяет структуру схемы; `src/form/FormTree.tsx` рисует его: списки с добавлением/удалением/перестановкой, необязательные блоки, переключатель `choice`, атрибуты, `nillable`.
4. **Валидация** — каждый простой тип превращается в zod-схему (`src/xsd/datatypes.ts`: паттерны XSD → RegExp, длины, enum, диапазоны, даты, totalDigits…); `src/xsd/validate.ts` дополнительно проверяет число вхождений, обязательные атрибуты, уникальность `xs:ID`.
5. **XML** — `src/xsd/xml.ts` сериализует дерево (namespace-префиксы, `xsi:nil`, порядок по схеме) и умеет читать XML обратно в форму («Загрузить XML»).

## Структура

```
*.xsd, *.xml            исходные схемы и пример документа
src/xsd/                движок: model, loader, datatypes (zod), instance, validate, sample, xml
src/form/               рендер формы и стор статуса/ошибок
src/components/         shadcn/ui-компоненты (src/components/ui) и панели
tests/                  vitest: загрузчик, типы, XML, e2e с xmllint
```

## Особенности входных схем

- В `WorkInfo.xsd` корневой элемент назван `workInfo rt` (пробел недопустим в XML-имени) — используется `workInfo`, замечание видно на вкладке «Схема».
- `WorkInfo.xsd` импортирует отсутствующий `RandomTest.xsd` — пропускается с предупреждением.
- `schemaLocation` вида `../types/X.xsd` разрешается по имени файла в корне.
- Для библиотечных схем (`CommonTypes.xsd` и т. д.) в списке «Корень формы» можно выбрать любой именованный сложный тип.
